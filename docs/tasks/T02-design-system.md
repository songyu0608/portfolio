## 목표

T03의 공통 레이아웃과 이후 페이지가 함께 사용할 디자인 토큰을 정하고 CSS로 구현한다. 일본어·영어 콘텐츠를 읽기 쉽게 보여주고, 라이트·다크 모드와 모션 감소 설정에서도 의미와 대비가 유지되게 한다.

## 배경

- `docs/PLAN.md` §2 확정 사항, §5 단계 2
- `docs/DESIGN.md` §1~3 디자인 원칙과 인터랙션 요구사항
- `docs/CONTENT.md`의 자격증 표기 규칙과 기술 스택 분류별 태그(시안 B). 이번에는 실제 콘텐츠를 만들지 않되 두 표현이 가능한 토큰을 마련한다.
- 주 독자는 일본 채용 담당자와 현업 엔지니어. 30초 안에 핵심 정보를 읽을 수 있는 가독성이 우선이다.

## 범위

포함:

- 라이트·다크 색상 후보, 일본어 본문과 영문·코드용 글꼴 후보를 확인 화면으로 제시하고 사용자(choi)의 선택을 받는다. 선택한 값만 `docs/DESIGN.md` §2의 확정 값으로 기록한다. 선택 전에는 후보라고 명시하고 프로젝트 결정으로 기록하지 않는다.
- 선택한 색상(background, surface, text, text-muted, accent, on-accent, border 및 필요한 상태색), 글꼴, 크기·줄높이, 4px 기반 간격, 모서리, 그림자, 모션 시간·easing을 토큰으로 정한다. 본문 최대 폭은 CSS 토큰으로, 반응형 전환점은 수치와 적용 위치를 문서에 명시한다.
- `src/styles/`에 재사용할 CSS 변수와 최소 전역 스타일을 구현한다. 기본은 시스템 테마(`prefers-color-scheme`)를 따르고, `<html data-theme="light">` 또는 `<html data-theme="dark">`가 있으면 그 값을 우선한다. T03의 수동 테마 전환 UI는 이 규칙을 재사용한다.
- 제목·본문·링크·버튼·포커스·테두리 태그·채운 주력 태그·카드의 기본 상태를 볼 수 있는 작은 디자인 확인 화면을 만든다. 일본어와 영어 문구는 별도 데이터에서 가져온다. 기존 `/ja/`, `/en/` 준비 페이지를 활용해도 된다. 채운 태그는 `on-accent`를 사용하고, 주력 여부를 색 외에도 전달할 수 있는 `sr-only` 유틸리티를 준비한다.
- 키보드 포커스를 볼 수 있게 하고, 본문·UI의 색 대비와 작은 모바일 화면에서의 가독성을 직접 확인한다. `prefers-reduced-motion: reduce`에서는 장식 모션이 꺼진다.
- 사용자 선택 후 확정한 색상·폰트·크기·간격과 선택 이유를 `docs/DESIGN.md`에 기록한다. 사용자 검토를 위해 후보 및 확정 시안의 라이트·다크, 모바일·데스크톱 화면을 PR 설명에 제시한다.

제외:

- 실제 Home/About/Projects/Contact 콘텐츠와 완성 페이지 (T03 이후)
- 헤더·푸터·언어 전환 및 수동 테마 전환 UI (T03)
- Hero 디코딩, 카드 틸트, 터미널, 명령 팔레트, 타임라인 동작 구현 (단계 5)
- 실제 기술 목록·자격증 원고 수집 (단계 4 전 별도 진행)
- Cloudflare 배포 (단계 8)

## 완료 조건

- [ ] 색상·글꼴 후보를 사용자(choi)에게 제시해 선택을 받고, 그 선택과 이유를 기록했다. `docs/DESIGN.md` §2의 T02 자리표시자는 선택한 실제 값으로 대체되어 있다.
- [ ] CSS 변수와 전역 스타일이 일본어·영어 확인 화면에 적용된다. 시스템 라이트·다크 설정과 `data-theme` 명시적 설정 모두 의도한 우선순위로 표시된다.
- [ ] [WCAG 2.2 AA 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)을 라이트·다크 두 테마에서 확인했다. 일반 텍스트는 4.5:1 이상, 큰 글자는 3:1 이상이다. [UI 식별에 필요한 경계·상태와 직접 스타일을 지정한 포커스 표시](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)는 인접 색상과 3:1 이상이다. 측정 도구·색상 조합·결과 수치와 작은 화면의 가독성 확인 결과를 PR에 기록하고 부족한 조합을 수정했다.
- [ ] 테두리 태그와 채운 주력 태그, `on-accent`, `sr-only`, 본문 최대 폭과 반응형 전환점이 확인 화면·문서에 반영되어 있다.
- [ ] 모션 감소 설정에서 장식 효과가 꺼지고 내용은 그대로 읽을 수 있다.
- [ ] `pnpm format:check`, `pnpm lint`, `pnpm check`, `pnpm build`와 GitHub CI가 통과한다.
- [ ] `docs/PLAN.md`의 단계 2·T02 상태가 갱신되고 비밀 값이 커밋되지 않았다.

## 확인 방법

```bash
pnpm install --frozen-lockfile
pnpm format:check && pnpm lint && pnpm check && pnpm build
pnpm dev
```

`/ja/`와 `/en/`을 데스크톱·작은 모바일 화면에서 확인한다. 시스템 라이트·다크 모드, `data-theme="light|dark"` 지정 시의 우선순위, 키보드 Tab 포커스, 모션 감소 설정을 각각 확인한다. PR에는 실제 확인한 화면·설정, 사용한 대비 측정 도구와 색상 조합별 결과를 적는다.

## 사용자 선택 결과 (2026-10-30)

후보 시안(claude.ai 디자인 캔버스, 비공개 링크)에서 choi가 아래를 선택했다. 범위의 "후보 제시 → 사용자 선택" 단계는 이것으로 끝났다. 구현은 이 값을 기준으로 하고, 확정 값과 이유는 구현 PR에서 `docs/DESIGN.md` §2에 기록한다.

### 색상: 시안 E「Blue」

| 토큰 | 라이트 | 다크 |
| --- | --- | --- |
| background | `#F7F9FC` | `#0B0F17` |
| surface | `#FFFFFF` | `#141A24` |
| text | `#121619` | `#E8ECF2` |
| text-muted | `#525A63` | `#9CA6B4` |
| border (장식용 구분선) | `#DDE1E6` | `#26303D` |
| accent | `#0F62FE` | `#78A9FF` |
| on-accent | `#FFFFFF` | `#0B0F17` |

- 시안 작성 시 계산한 대비(WCAG 2.x 상대 휘도 공식): 라이트 본문 17.3:1, 보조 6.6:1, 링크(accent/background) 4.7:1, 채운 태그(on-accent/accent) 5.0:1. 다크 본문 16.2:1, 보조 7.1:1, 링크 7.4:1, 채운 태그 8.1:1. 구현 PR에서 도구로 재측정한다.
- 라이트의 링크 대비 4.7:1은 기준 4.5:1에 가깝다. accent 위에 다른 색을 겹치거나 background보다 어두운 면에 링크를 둘 때는 다시 측정한다.
- accent는 IBM 디자인 시스템(Carbon)의 Blue 60/40과 같은 값으로 알려진 색이다(공식 가이드로 재확인하지 않음). 상태색(성공·경고·오류)은 이 시안에 없으므로 구현에서 정하고 대비를 기록한다.
- 테두리 태그의 테두리는 시안에서 `text-muted` 색을 썼다. `border` 토큰은 카드 구분선 등 장식용이다.

### 글꼴: 시안 3「IBM Plex」

- 본문: IBM Plex Sans JP (400, 700), 코드·보조 라벨: IBM Plex Mono (400). 라이선스는 SIL OFL.
- 시안은 Google Fonts에서 불러왔다. 구현에서는 Google Fonts 사용과 자체 호스팅(`public/` 또는 Astro 폰트 기능) 중 하나를 고르고, 전송 크기·요청 수와 선택 이유를 PR에 적는다. 일본어 글꼴은 파일이 크므로 `font-display: swap`과 시스템 글꼴 대체(Hiragino Sans, Yu Gothic UI, Meiryo 등)를 둔다.

### 시안에서 쓴 기준값 (확정 아님, 구현에서 조정 가능)

- 본문 16px / 줄높이 1.8(일본어), 보조 텍스트 14px, h1 32px
- 모서리: 버튼 8px, 카드 12px, 태그 999px(알약형)
- 포커스 표시: `outline: 2px solid accent; outline-offset: 3px`

### 색 변경 방식

사이트 색은 토큰 파일의 값을 바꿔 사이트 전체를 바꾸는 방식으로 운영한다. 회사별 페이지마다 강조색을 바꾸는 구조는 만들지 않는다 (2026-10-30 사용자 결정).

## 메모

- 토큰 이름은 컴포넌트의 의미를 나타내게 정한다. 특정 페이지·색상에 묶인 이름은 피한다.
- 글꼴 외부 요청이나 큰 파일을 도입할 때는 성능·사용 권한을 확인하고 선택 이유를 PR에 적는다. 시스템 글꼴만으로 충족되면 새 자산이 필요 없다.
- 색상·글꼴 후보는 선택할 수 있을 만큼 차이와 장단점을 함께 제시한다. 선택 전 구현은 비교용 시안이며, 사용자 선택이 끝나야 완료 조건을 충족한다.
