## 목표

T03의 공통 레이아웃과 이후 페이지가 함께 사용할 디자인 토큰을 정하고 CSS로 구현한다. 일본어·영어 콘텐츠를 읽기 쉽게 보여주고, 라이트·다크 모드와 모션 감소 설정에서도 의미와 대비가 유지되게 한다.

## 배경

- `docs/PLAN.md` §2 확정 사항, §5 단계 2
- `docs/DESIGN.md` §1~3 디자인 원칙과 인터랙션 요구사항
- `docs/CONTENT.md`의 자격증 표기 규칙과 기술 스택 분류별 태그(시안 B). 이번에는 실제 콘텐츠를 만들지 않되 두 표현이 가능한 토큰을 마련한다.
- 주 독자는 일본 채용 담당자와 현업 엔지니어. 30초 안에 핵심 정보를 읽을 수 있는 가독성이 우선이다.

## 범위

포함:

- `docs/DESIGN.md` §2의 미정 값을 확정한다. 라이트·다크 색상(background, surface, text, text-muted, accent, border 및 필요한 상태색), 일본어 본문과 영문·코드용 글꼴, 크기·줄높이, 4px 기반 간격, 모서리, 그림자, 모션 시간·easing을 명시한다.
- `src/styles/`에 재사용할 CSS 변수와 최소 전역 스타일을 구현한다. 시스템 테마(`prefers-color-scheme`)에 따라 두 테마가 동작하고, 향후 수동 테마 전환(T03)이 토큰을 재사용할 수 있게 설계한다.
- 제목·본문·링크·버튼·포커스·태그·카드의 기본 상태를 볼 수 있는 작은 디자인 확인 화면을 만든다. 일본어와 영어 문구는 별도 데이터에서 가져온다. 기존 `/ja/`, `/en/` 준비 페이지를 활용해도 된다.
- 키보드 포커스를 볼 수 있게 하고, 본문·UI의 색 대비와 작은 모바일 화면에서의 가독성을 직접 확인한다. `prefers-reduced-motion: reduce`에서는 장식 모션이 꺼진다.
- 확정한 색상·폰트·크기·간격과 선택 이유를 `docs/DESIGN.md`에 기록한다. 사용자 검토를 위해 라이트·다크, 모바일·데스크톱 화면을 PR 설명에 제시한다.

제외:

- 실제 Home/About/Projects/Contact 콘텐츠와 완성 페이지 (T03 이후)
- 헤더·푸터·언어 전환 및 수동 테마 전환 UI (T03)
- Hero 디코딩, 카드 틸트, 터미널, 명령 팔레트, 타임라인 동작 구현 (단계 5)
- 실제 기술 목록·자격증 원고 수집 (단계 4 전 별도 진행)
- Cloudflare 배포 (단계 8)

이 목록 밖의 파일을 수정해야 하면 PR 설명에 이유를 적는다.

## 확인 방법

```bash
pnpm install --frozen-lockfile
pnpm format:check && pnpm lint && pnpm check && pnpm build
pnpm dev
```

`/ja/`와 `/en/`을 데스크톱·작은 모바일 화면에서 확인한다. 시스템 라이트·다크 모드, 키보드 Tab 포커스, 모션 감소 설정을 각각 확인한다. PR에는 실제 확인한 화면·설정과 대비 확인 결과를 적는다.

## 메모

- 토큰 이름은 컴포넌트의 의미를 나타내게 정한다. 특정 페이지·색상에 묶인 이름은 피한다.
- 글꼴 외부 요청이나 큰 파일을 도입할 때는 성능·사용 권한을 확인하고 선택 이유를 PR에 적는다. 시스템 글꼴만으로 충족되면 새 자산이 필요 없다.
- 사용자가 디자인 시안을 보고 선택해야 할 부분은 PR에 후보와 차이를 제시한다. 확정 전에는 임의의 선택을 프로젝트 결정으로 기록하지 않는다.
